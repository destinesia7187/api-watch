# Release acceptance evidence

This maps the 36 cases in [the specification](../TECHNICAL_SPECIFICATION.md) to concrete tests, scripts, or operational checks. It does not equate implementation, a skipped test, and a measured acceptance result. Run the committed commands against the intended commit and retain the actual output.

## Reproduce automated checks

Install the locked dependencies and use an isolated PostgreSQL test database. Set `TEST_DATABASE_URL` to a `postgresql+psycopg://...` connection before running `python -m pytest -q`. Without it, PostgreSQL parametrizations and race tests are explicitly skipped; SQLite is not evidence for PostgreSQL locking. Do not point this variable at a production database.

Run `python -m ruff check api_watch tests scripts`, `node --check api_watch/static/app.js`, and `node scripts/test_frontend.cjs` as well. The [CI workflow](../.github/workflows/ci.yml) also applies migrations, checks migration/model drift, validates the exported OpenAPI snapshot, and builds a container in a separate job. A committed CI configuration is not a claim that a remote GitHub run has occurred.

The Node suite exercises the shipped client code in a small VM/DOM harness. It is useful regression coverage for browser utilities, precise JSON, forms, pagination periods and display semantics; it is not a real browser end-to-end runner.

Recorded release result: **277 backend tests passed, zero failures/errors, and three SQLite parametrizations of PostgreSQL-only tests skipped**; their real PostgreSQL counterparts passed. All **15 frontend regressions** passed. The [validation report](evidence/validation.json), [full load report](evidence/load-test.json), [real worker recovery report](evidence/worker-recovery.json), and [backup restore report](evidence/backup-restore.json) retain the actual measured scope. All ten full-load acceptance assertions passed.

## Deployment and credential checks

These checks require the intended environment or owner-provided credentials. They are not hidden feature exclusions:

- Configure the owner's actual Telegram bot, consume a private-chat link, send a test and observe opening/recovery messages. CI substitutes an adapter and never sends to a real chat.
- Configure production SMTP and verify a reset message reaches the intended inbox using the required transport policy. The SMTP adapter test does not verify a provider's credentials or deliverability.
- Validate the actual HTTPS reverse proxy, public origin, Secure cookies, egress/firewall routing, private database exposure and registration policy. Local fixtures do not prove cloud-network isolation.
- Build and start Compose on a machine with a working Docker engine. Configuration parsing and a checked-in container build job do not replace an observed clean deployment.
- Extend browser verification to the intended mobile devices and assistive technologies. The recorded run includes a narrow desktop viewport, keyboard focus checks and chart-size regressions; it does not claim device certification.
